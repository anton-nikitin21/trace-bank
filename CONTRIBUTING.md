# Работа команды

Репозиторий публичный: любой участник с аккаунтом GitHub может предложить изменение через fork и pull request. Прямой push доступен владельцу и добавленным Collaborators. Публичность не дает анонимную запись в main.

1. Создайте Issue и согласуйте границы задачи.
2. Получите актуальную main: `git switch main`, затем `git pull --ff-only`.
3. Создайте ветку: `git switch -c feature/short-name` или `fix/short-name`.
4. Изменяйте `website/` для сайта, `app/` для локального API, `sprint-1/` для материалов.
5. Выполните проверки из README, проверьте пользовательский сценарий.
6. Выберите файлы: `git add website docs` (укажите свои пути), затем `git commit -m "Describe the change"`.
7. Отправьте ветку: `git push -u origin feature/short-name`; откройте PR в main. Укажите проверку и скриншоты.
8. После ревью и успешных Checks владелец/участник с правом записи объединяет PR. После merge main публикуется GitHub Pages.

Без Write: нажмите Fork, клонируйте свою копию и откройте PR из своей ветки в `anton-nikitin21/trace-bank:main`.

Коммиты создаются участниками осознанно; автоматическая отправка каждого сохранения файла не включена.

Не коммитьте `.env`, токены, реальные комплекты, SQLite и содержимое браузерного хранилища. Clerk Publishable Key — публичный, Secret Key всегда остается на сервере. Не запускайте `app/build_portable.py` для обновления рабочего сайта: это исторический генератор корневого демо, он не собирает современную очередь.

Рекомендуемые настройки владельца: защита main, запрет force-push, один approval и обязательная проверка `Checks / check`. Эти настройки нужно включить в GitHub; файл инструкции не применяет их автоматически.
