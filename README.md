# Trace — рабочее место сотрудника банка

Направление 3: собственная эффективность банка. Trace сопоставляет операции бизнес-клиента с документами, показывает пробелы по учебному профилю и помогает подготовить адресное уточнение. Решение остается за сотрудником.

[Рабочее приложение](https://anton-nikitin21.github.io/trace-bank/workspace.html) · [Главная](https://anton-nikitin21.github.io/trace-bank/) · [Как работать командой](CONTRIBUTING.md)

## Быстрый запуск
субо лох мне пох
fdfdfd
Нужны Python 3.10+ и Node.js 22+ для проверок. Сайт не требует установки npm-пакетов.

```sh
git clone https://github.com/anton-nikitin21/trace-bank.git
cd trace-bank
python -m http.server 8766 --bind 127.0.0.1 --directory website
```

Откройте http://127.0.0.1:8766/workspace.html . В командах используйте `python3` вместо `python`, если так называется установленный Python. Альтернатива: `npm run dev`.

## Что уже работает

Очередь трех вымышленных клиентов, поиск и статусы; карточка обращения; проверка 3 операций; переход к строкам источника; редактирование TXT; проект уточнения; повторная проверка; фиксация сотрудником; журнал изменений; восстановление браузерного демо после перезагрузки. Начальный комплект дает 4 замечания, дополненный — 0 и 3/3 групп без замечаний.

Каждый посетитель имеет отдельное локальное браузерное хранилище. Общей банковской базы и совместного редактирования кейсов нет. Совместная работа команды в GitHub относится к исходникам. Публичный сайт использует только вымышленные примеры.

## Структура

| Папка | Назначение |
|---|---|
| website/ | Актуальный сайт и рабочий кабинет Clerk workspace.html |
| app/ | Отдельный локальный Python API, движок правил, SQLite и тесты |
| scripts/ | Проверки сайта и браузерного движка, синтетический benchmark |
| sprint-1/ | Презентация, исследования, экономика и материалы первого спринта |
| docs/ | Clerk, публикация и разбор задач |
| .github/ | CI, GitHub Pages, шаблоны задач и PR |

Ранние корневые demo.html, pitch/, research/ и материалы с именем «Основание» сохранены как история. Основной сайт редактируйте только в website/. `app/build_portable.py` собирает историческое корневое демо, не современный сайт.

## Проверки перед коммитом

```sh
python -m unittest discover -s app -v
python scripts/check_project.py
node scripts/test_browser_engine.cjs
python scripts/build_workspace.py --check
node scripts/test_auth.cjs
```

Проверяются правила и API, локальные ссылки и синтаксис JavaScript, а также фактический браузерный движок на исходном и дополненном комплекте. GitHub Actions выполняет те же проверки при push и PR.

Дополнительно: `python scripts/benchmark.py` воспроизводит синтетический набор и обновляет отчеты sprint-1/reports/. Это не независимое исследование банковского качества.

## Локальная серверная версия

```sh
cd app
python server.py
```

Адрес http://127.0.0.1:8765 . Это отдельный прототип с SQLite; у него нет очереди современной статической версии, Clerk-проверки токенов или изоляции организаций. Не размещайте его в открытом доступе как готовый B2B backend.

## Публикация и доступ

После включения GitHub Pages в Settings → Pages → GitHub Actions каждый push в main проходит проверки и публикует website/. Ветки и PR проверяются без публикации. Текущий адрес Sites обновляется отдельно. Подробности: [docs/DEPLOYMENT.md](docs/DEPLOYMENT.md).

Репозиторий публичный: любой пользователь GitHub может сделать fork и предложить PR. Прямую запись получают только приглашенные Collaborators. Команда работает через отдельные ветки, ревью и merge; инструкция в [CONTRIBUTING.md](CONTRIBUTING.md).

## Авторизация и ограничения

Кабинет с актуальной очередью подключен к тестовому приложению Clerk. Форма входа активирована; для доступа сотрудник должен состоять в организации приложения. Учебное хранилище кабинета разделено по пользователю и организации. Настройка описана в [docs/CLERK-SETUP.md](docs/CLERK-SETUP.md). Никогда не помещайте Secret Key в браузер или коммит. Для банковского внедрения нужны серверные права, изоляция организаций и корпоративный SSO.

OCR произвольных сканов, подлинность и достаточность для банковского решения не проверяются. Экономия времени пока является гипотезой пилота. Текущая библиотека Three.js включена с ее MIT-лицензией в website/assets/vendor/THREE-LICENSE.txt.

Шаблон рабочего кабинета: `templates/workspace.html`. Он хранится вне публикуемой папки; `scripts/build_workspace.py` собирает из него страницу с обязательным входом Clerk. Старый адрес `demo.html` перенаправляет на вход.

### Общедоступная демонстрация

Открыть без регистрации: https://anton-nikitin21.github.io/trace-bank/demo.html

Демо начинает работу с обучения и содержит вымышленные обращения. Каждая ссылка открывает отдельную сессию в браузере посетителя. Файлы и результаты не синхронизируются между пользователями. Кабинет `workspace.html` сохраняет вход через Clerk.

`python scripts/build_workspace.py` собирает публичное демо и кабинет из одного шаблона; `--check` проверяет обе страницы.
