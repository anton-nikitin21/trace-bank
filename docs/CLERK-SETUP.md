# Вход сотрудников через Clerk

## Реализовано

- `website/workspace.html` содержит актуальную очередь, карточки и журнал, собранные из demo.html.
- ClerkJS 6 + Clerk UI 1: вход/регистрация, профиль, выход, выбор и переключение организации.
- До входа и выбора организации очередь не запускается и интерфейс скрыт. При потере сессии или смене организации он закрывается сразу, страница перезагружается.
- Учебное браузерное хранилище кабинета разделено по user_id и organization_id. Публичное demo.html имеет отдельное хранилище.
- Публичная главная, материалы и demo.html доступны без регистрации.
- Ошибка загрузки дает кнопку повторного подключения; пользователь без организации может выйти из аккаунта.

## Активация

1. В https://dashboard.clerk.com/ выберите или создайте приложение Trace. Выберите способы входа и включите Organizations.
2. Скопируйте **Publishable Key** из API Keys (`pk_test_…` для разработки, `pk_live_…` для production). Запишите его в `website/assets/auth-config.js`. Это публичная конфигурация, она попадет в браузер; Secret Key сюда не добавлять.
3. В Dashboard создайте учебную организацию и пригласите сотрудников. Ограничьте самостоятельное создание организаций согласно вашей модели доступа. Скрытая кнопка в интерфейсе не заменяет ограничение в Clerk.
4. Для production настройте домен и redirect/origin параметры приложения по инструкции Clerk. Кабинет GitHub Pages: https://anton-nikitin21.github.io/trace-bank/workspace.html . Для копии Sites используйте ее отдельный домен. Не добавляйте весь github.io в разрешенные redirect-адреса.
5. После коммита в main GitHub Pages опубликует конфигурацию. Домен Sites требует отдельного обновления. Ключи production и development принадлежат разным окружениям.
6. Проверьте вход новым и существующим пользователем, создание учетной записи (если разрешено), приглашение, отсутствие организации, выход, истечение сессии и переключение двух организаций.

Пока реальный ключ не добавлен, вход не активирован. Не используйте заглушку как настоящий ключ и не объявляйте проверку stub SDK проверкой внешнего сервиса.

## Разработка и проверка

`website/demo.html` — источник интерфейса. После его изменений выполните:

```sh
python scripts/build_workspace.py
python scripts/build_workspace.py --check
python scripts/check_project.py
node scripts/test_auth.cjs
node scripts/test_browser_engine.cjs
```

Генератор обновляет только кабинет и сохраняет привязку к текущему сценарию. Не редактируйте сгенерированный workspace.html вручную. Проверки авторизации используют подменный SDK и проверяют блокировку, запуск, смену организации, выход и ошибки сети. Проверка настоящих писем, OAuth и приглашений выполняется с вашим приложением Clerk.

## Граница защиты

Это аутентификация интерфейса учебного статического кабинета. HTML и встроенные вымышленные данные публичны; локальное хранилище пользователь может изменять. Оно не является серверным разграничением прав или защищенным аудитом.

`app/server.py` — отдельный локальный прототип. Он не получает и не проверяет Clerk JWT. Для реальных кейсов нужны сервер с проверкой подписи/issuer/срока/authorized parties, права на каждое действие и фильтрация всех сущностей по организации из проверенной сессии. GitHub Pages серверный API не исполняет.

Для закрытого банковского контура нужен адаптер корпоративного SSO/OIDC. Не загружайте реальные клиентские документы в текущую публичную версию.

Официальная инструкция SDK: https://clerk.com/docs/js-frontend/getting-started/quickstart
