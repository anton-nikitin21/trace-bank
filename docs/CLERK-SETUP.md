# Clerk: подготовленная интеграция

Изменена копия статического сайта website/. Публичная главная и аналитика доступны без входа. workspace.html закрыт экраном входа; без ключа показано понятное сообщение, обхода входа нет.

Реализованы загрузка ClerkJS 6 и UI 1, вход/регистрация через стандартный SignIn, профиль/выход через UserButton, выбор организации и переключение организаций. При смене пользователя или организации страница перезагружается, чтобы не переносить открытый комплект между контекстами. Используются только синтетические данные исходного демо.

## Осталось настроить

1. Создать приложение в https://dashboard.clerk.com/ и настроить способы входа.
2. Включить Organizations. Организации и приглашения создает администратор. Ограничить создание организаций и регистрацию/доступ по выбранной политике в Dashboard: скрытая кнопка не является запретом на сервере.
3. Записать Publishable Key pk_test_… в website/assets/auth-config.js. Это публичный ключ; Secret Key в браузер не помещать.
4. Добавить домен развертывания и адрес рабочего места в настройки приложения Clerk, проверить разрешенные redirect/origin настройки.
5. Проверить вход, выход, приглашение, пользователя без организации, переключение двух организаций, истекшую сессию и ошибку загрузки. Проверить реальный вход пока невозможно: по просьбе пользователя ключ не добавлялся.
6. Опубликовать обновление существующего сайта из аккаунта владельца. В текущем подключении Sites этот сайт не найден; опубликованное демо не изменено.

## Граница реализации

Это интеграция аутентификации интерфейса синтетического статического демо. HTML, исходные примеры и скачиваемые материалы остаются публичными. Скрытие интерфейса не защищает данные. Python app/server.py из исходного архива не изменен и пока не проверяет Clerk-токены. Не выставлять его как защищенный B2B backend.

Для настоящего B2B: проверять подпись JWT, issuer, срок и authorized parties на сервере; получать user_id/org_id из проверенного токена; проверять членство и права на каждый запрос; хранить org_id в каждой сущности и фильтровать все чтения/записи по нему. Добавить роли, журнал и тест доступа к чужой организации. Пользователь не должен задавать доверенный org_id через тело запроса.

Для банковского пилота подготовить заменяемый адаптер корпоративного SSO/OIDC в контуре. Облачный Clerk в демо не доказывает готовность к закрытому контуру.

Документация: https://clerk.com/docs/js-frontend/getting-started/quickstart
