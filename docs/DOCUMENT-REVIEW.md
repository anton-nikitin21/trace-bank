# Загрузка и проверка документов

Изменение относится только к рабочему кабинету. Главная страница, общие стили бренда и Clerk остаются прежними.

## Сценарий сотрудника

1. Открыть обращение или создать новое.
2. Добавить договор, акт, УПД или пояснение в PDF, PNG, JPG/JPEG или TXT.
3. Открыть «Проверить и дополнить». Сверить распознанные поля с исходным текстом/оригиналом. Неизвестные поля заполнить вручную, несколько найденных вариантов выбрать по документу.
4. Подтвердить поля. Ручные значения отмечаются отдельно и не изменяют исходный текст.
5. Указать платежи для сравнения. В учебных обращениях платежи уже заполнены.
6. Запустить проверку, посмотреть расхождения и подготовить запрос клиенту.
7. После дополнения повторить проверку и завершить работу с комментарием.

Действия, статусы и распознанные сведения сохраняются в браузере в существующем пространстве пользователя/организации. Оригиналы PDF и изображений находятся только в памяти текущей вкладки. После перезагрузки доступны извлечённый текст и подтверждённые поля; для повторного просмотра оригинала его нужно загрузить снова.

## Обработка файлов

- Текстовый PDF: PDF.js 6.4.299 извлекает текст.
- Страница PDF с менее чем 30 непробельными символами: страница отрисовывается и передаётся в Tesseract.js 7.0.0.
- PNG/JPEG: Tesseract.js распознаёт русский и английский текст.
- TXT: читается непосредственно.
- Извлечение реквизитов выполняется консервативными правилами. Пропущенные и неоднозначные поля остаются пустыми, данные из платёжного примера не используются для их заполнения.
- Для сравнения с платежами формируется нормализованный текст старого формата Trace. Исходный текст хранится отдельно в `sourceText`; подтверждение и происхождение значений в `review`.
- «Сумма без НДС» и «НДС» не принимаются за итоговую сумму. Даты проверяются по календарю. Несколько ИНН требуют выбора сотрудником.
- Перед анализом обязательны тип, номер, номер договора, ИНН и дата. Для акта и УПД также требуется итоговая сумма. Оригинальные учебные TXT совместимы с прежним движком.

Файлы не отправляются на сервер распознавания. При первом запуске браузер получает библиотеки, WebAssembly и языковые модели из внешних источников. Файлы, их содержимое и имена не включаются в эти запросы. Внедрение в банковский контур требует локального размещения зависимостей и замены учебного браузерного хранения на согласованное серверное хранилище.

## Локальные зависимости для закрытого контура

До загрузки `document-reader.js` можно определить `window.TRACE_DOCUMENT_PATHS` с адресами файлов той же версии:

```js
window.TRACE_DOCUMENT_PATHS = {
  pdf: '/vendor/pdfjs/build/pdf.mjs',
  pdfWorker: '/vendor/pdfjs/build/pdf.worker.mjs',
  pdfFonts: '/vendor/pdfjs/standard_fonts/',
  pdfCmaps: '/vendor/pdfjs/cmaps/',
  pdfWasm: '/vendor/pdfjs/wasm/',
  tesseract: '/vendor/tesseract/tesseract.min.js',
  worker: '/vendor/tesseract/worker.min.js',
  core: '/vendor/tesseract-core',
  lang: '/vendor/tessdata'
};
```

`core` должен содержать все сборки tesseract.js-core 7.0.0, чтобы библиотека выбрала подходящий вариант. `lang` должен содержать `rus.traineddata.gz` и `eng.traineddata.gz`, совместимые с Tesseract. Соблюдайте лицензии библиотек и моделей. По умолчанию используются закреплённые версии jsDelivr и языковые данные tessdata.projectnaptha.com/4.0.0. Vercel публикует существующую папку `website`, отдельный API и секретный ключ не нужны.

## Ограничения

До 10 файлов за одну загрузку, 20 МБ на файл, 20 страниц в PDF, 100 000 символов текста, 12 мегапикселей для OCR изображения/отрисованной страницы. Для большого изображения уменьшается отрисовка PDF; слишком большие отдельные изображения отклоняются. Документы с паролем, повреждённые файлы, рукопись, сложные таблицы и неоднозначные поля могут потребовать нового файла или ручного ввода. Ошибки чтения не заменяют предыдущую подтверждённую версию файла.

Распознавание не проверяет подписи и подлинность документов, а отсутствие замечаний не одобряет банковскую операцию. Если текстовый PDF содержит только частичный текстовый слой, автоматическое определение необходимости OCR может быть недостаточным. Аналитик проверяет все поля.

Хранение остаётся учебным localStorage с прежней изоляцией по аккаунту/организации, не защищённой банковской базой. Ограничения квоты показываются существующим статусом хранения.

## Проверки

```sh
python -m unittest discover -s app -v
python scripts/check_project.py
python scripts/build_workspace.py --check
python scripts/build_preview.py --check
node scripts/test_browser_engine.cjs
node scripts/test_auth.cjs
node scripts/test_document_reader.cjs
```

DOM-проверка всей цепочки (нужен установленный `linkedom@0.18.12`):

```sh
TRACE_DOM_MODULE=/path/to/node_modules/linkedom node scripts/test_document_workflow.cjs
```

При разработке дополнительно проверены реальные PDF.js и Tesseract.js на синтетических текстовом PDF, скане PDF, PNG и JPEG через Node-адаптер canvas. В четырёх случаях получены ожидаемые ИНН, сумма, дата и номера. Это проверка воспроизводимости сценария, не независимая оценка банковского качества. Внешний браузер тестовой среды не имеет доступа к локальному серверу; визуальная проверка и CDN-загрузка в браузере пользователя требуют приёмки preview-развёртывания.
