# Серверный редактор требований

Установить зависимости командой python -m pip install -r app/requirements.txt.
Запустить python app/storage_server.py.
Открыть http://127.0.0.1:8770/workspace.html и войти через Clerk с выбранной организацией.

Раздел «Редактор требований» расположен в боковом меню кабинета. В публичном демо форма доступна для просмотра, а запись требует серверного входа. Нажмите «Загрузить реестр». Пользователь с ролью org:editor сохраняет черновик. Пользователь с ролью org:admin сохраняет и утверждает версии. Остальные роли имеют чтение. Для утверждения сначала сохраните черновик. Изменённый текст требуется сохранить новой версией перед утверждением. Дата вступления и обязательность являются метаданными реестра. Подключение опубликованных правил к движку сверки выполняется отдельно.

Подпись сессии проверяется по JWKS настроенного приложения. Проверяются RS256, issuer, exp, nbf, iat, sub, sid, azp и активная организация. TRACE_CLERK_ISSUER и TRACE_AUTHORIZED_PARTIES задаются на сервере. По умолчанию разрешены localhost и 127.0.0.1 на порту 8770. Выход прекращает отправку новых токенов клиентом. Уже выданный JWT действует до истечения своего короткого срока. Мгновенный отзыв через Backend API Clerk здесь не реализован.

При переходе на другого пользователя или организацию заново загрузите реестр. Сервер фильтрует все записи по организации проверенного токена. Не назначайте общий персональный API-токен нескольким сотрудникам. Локальное хранилище SQLite следует размещать вне публикуемой папки и ограничить права ОС.

Протестированы локальные подписанные JWT. Реальный вход в аккаунт Clerk и выдача ролей в Dashboard требуют отдельной проверки.
